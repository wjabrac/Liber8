1. **`main.py` ignores CLI arguments (`sys.argv`)**
   - **Impact: High.** Prevents executing subcommands like `healthcheck` or `serve` via the root `main.py` script. The CLI always falls back to the default hardcoded cognition loop run.
   - **Estimated fix difficulty: Trivial.** Pass `sys.argv[1:]` to `cli_main()`.

2. **`postgres_store.py` summary crashes on connection failure**
   - **Impact: High.** Causes the service `healthcheck` API to crash (HTTP 500) if the database goes down or name resolution fails, instead of cleanly reporting a degraded state in the JSON response.
   - **Estimated fix difficulty: Easy.** Add a try/except block around `psycopg.connect()` in `summary()` to catch exceptions and return an offline state.

3. **`test_live_postgres.py` assumes running local DB**
   - **Impact: Medium.** The local test suite deterministically crashes for developers missing an active PostgreSQL instance mirroring production settings on port 5432.
   - **Estimated fix difficulty: Easy.** Decorate the class or test with `@unittest.skipIf` checking for an environment variable like `LIVE_POSTGRES_OPTOUT` or `TEST_LIVE_POSTGRES`.

4. **Missing `pytest` in virtual environment**
   - **Impact: Low.** The standard test runner used historically, and possibly in CI or local scripts like `test_live.sh`/external tools natively assumes `pytest` works, resulting in confusing "command not found" errors upon clone.
   - **Estimated fix difficulty: Trivial.** Add `pytest` to dependencies or document standard testing via `python -m unittest`.

5. **`test_live.sh` assumes service runs on :8080 already**
   - **Impact: Low.** Causes test_live.sh script to fail with "connection refused" if the user hasn't explicitly started `python main.py serve` in a secondary terminal first. 
   - **Estimated fix difficulty: Easy.** Make the script spawn the server, wait for it, run pings, and tear down; or document prerequisites clearly.
